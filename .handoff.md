## 4. The 2 Remaining Failures — root cause (re-diagnosed)

Both in `tests/e2e/specs/export-pdf.spec.ts`. **Not** the cuid cascade #1084 originally predicted.

The tests call `page.request.post("/api/export-pdf", …)`, which issues the request from the **Playwright Node process, not the browser**. But `interceptBrowserlessPdf()` registers `page.route("**/chrome.browserless.io/pdf**", …)`, and `page.route` only intercepts traffic from the **browser context**. The route handler's own `fetch()` to Browserless runs server-side, so the interception never fires — the **real** Browserless API is hit with the dummy key and returns 401:

```
[WebServer] {"event":"export_pdf_browserless_error","status":401} Please sign-up for an account at https://browserless.io/
```

`:92` expects a mocked 503 but gets 401; `:36` expects 200 but gets 401. Test `:82` passes *only* because it never logs in and never registers the interception — the 401 there is the real, correct auth failure.

Three fixes are written up on #1084. Cheapest sound one: **drive the request from the browser** so `page.route` applies. Deleting the two tests as redundant is also defensible — `export.spec.ts:34`/`:45` already cover the success and outage paths through the real button click.
