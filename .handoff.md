## 6. Traps Hit or Confirmed This Session

- **Check whether a premise is still true before building on it.** The prior handoff's "needs a scoped run" advice was confidently wrong, and acting on it would have produced a much worse design (a second Playwright project) or a broken suite. #784 moved the counter to Postgres; the module header in `lib/api-quota.ts` says so in three places.
- **To prove an e2e test bites, perturb the *input* to the boundary, not the seam.** Reverting a resolver sends a real request at a paid API; here, seeding `limit - 1` instead of `limit` makes the route serve a PDF. Same lesson as the prior session's dead-port trick, generalized: mutate the cheapest thing between the test and the assertion.
- **Any test that writes shared state must undo it, and the undo needs its own guard.** The `seeded` flag in `withExportUsageAtLimit` exists because a `finally` that deletes a row it never wrote is its own bug. Assert the *absence* of side effects too (this spec asserts zero Browserless calls on the 429 path).
- **Duplicated constants can be a feature if you pin them from both sides.** `E2E_DAILY_EXPORT_LIMIT` mirrors `DEFAULT_DAILY_EXPORT_LIMIT` instead of importing it (no spec imports app source), and the test asserts the route's own reported `limit` — so a change to the app default fails loudly instead of silently no-op-ing.
- **`prisma db push` attempt 1/5 failing at the start of a run is normal** — the container's published port lags its own readiness. The retry loop handles it; the second attempt succeeds. Don't read it as a failure.
- **The Postgres `E57P01` FATAL lines at the end of a run are teardown noise** (the disposable container is removed while the Next server still holds connections), not a test failure. Same for `[WebServer] Error: The destination stream closed early`.
- **Don't quote the hash of a commit inside the file that commit carries.** Writing one into `.handoff.md` makes it stale on the next amend — this cost two extra commits in a prior session. Use `git log -N` instead.
- **A `next build` (implying `npm run e2e`) re-dirties `tsconfig.json`**, and running vitest re-dirties the tracked-but-ignored cache file in §5.5. Both fired this session; read the full path before staging.
- **`ls tests/` does not recurse** — use `git ls-files 'tests/**'`. A v1 route test already existed under `tests/api/`.
- **A test that mocks a module must be updated when that module's export surface changes** — `vi.mock` factories here are allowlists, not passthroughs, so a new import makes the export `undefined` and the handler 500s.
