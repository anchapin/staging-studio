## 6. Traps Hit or Confirmed This Session

- **To prove an e2e test bites, break the *override target*, not the seam.** Reverting `resolveBrowserlessPdfUrl` back to `buildBrowserlessPdfUrl` in the route — the method used to prove the seam in the prior session — would send a real request to `chrome.browserless.io` with a dummy key. Pointing `E2E_BROWSERLESS_PDF_URL` at a dead port instead produces the same "the request did not land on the mock" condition with **zero** external traffic. Use that method for anything touching a paid provider. (The prior session's revert was safe only because a dummy key just 401s; do not assume that is free.)
- **The mock's captured-request log is process-wide, shared for the whole suite run, and never cleared.** `mockBrowserlessRequests()[0]` — which the unversioned `export-pdf.spec.ts` uses — is correct *only* because that suite's success test runs first. A second spec reading index `0` would silently assert against the *previous* spec's captured request. Take a count delta before the request and slice (the new spec's `freshBrowserlessRequests()`).
- **A `next build` (implying `npm run e2e`) re-dirties `tsconfig.json`.** Reverted before staging. The `jsx: "preserve"` → `"react-jsx"` flip was the *only* hunk; confirmed by reading the diff before reverting.
- **A tracked-but-gitignored vitest cache file rides along in `git diff --stat`.** Both predicted traps reappeared this session; read the full path before staging.
- **The two export routes answer upstream failures differently, and neither is obviously the intended behavior.** `/api/export-pdf` propagates; `/api/v1/export-pdf` hard-codes 500. Whether the v1 flattening is deliberate (a v1 "stable contract" choice) or an oversight is **unknown** — worth a decision, but the spec now pins current behavior either way, so changing it requires a deliberate test edit, not a silent fix.
