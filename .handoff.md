## 4. The 2 Remaining Failures — both #1084

`tests/e2e/specs/export-pdf.spec.ts:36` and `:92`. **Root cause (re-diagnosed, not the predicted cuid cascade):**

The tests call `page.request.post("/api/export-pdf", …)`, which issues the HTTP request from the **Playwright Node process, not the browser**. But `page.route("**/chrome.browserless.io/pdf**", …)` only intercepts requests from the **browser context**. The route handler's own `fetch()` to Browserless runs server-side, so the interception never fires — the **real** Browserless API is hit with the dummy key and returns 401:

```
[WebServer] {"event":"export_pdf_browserless_error","status":401} Please sign-up for an account at https://browserless.io/
```

`:36` asserts 200 (gets 401), `:92` asserts 500 (gets 401). The third test `:82` passes only because it never logs in and never registers the interception.

Three fixes are documented on #1084. Cheapest sound option: **drive the request from the browser** (`page.evaluate(() => fetch(...))`) so `page.route` applies. Deleting the two tests as redundant also works — `export.spec.ts:34`/`:45` already cover the success and outage paths through the real button click.
