## Diagnosis (confirmed via DB sanity check)

- ✅ Server action clears `Room.afterImageUrl` correctly (DB check passes).
- ✅ InpaintVersion rows for `variantSlot=0` are hard-deleted.
- ❌ `<VersionStrip>` still renders the X icon for variant A after delete.
- ❌ `state.viewing` does not transition to the expected fallback slot.

The X icon is gated on `v.url` (i.e. `lookbookVariantUrls.A`). After
`revalidatePath` + `router.refresh()`, `lookbookVariantUrls.A` should become
null. **It is not** within the test's 20s polling window. This points to a
`router.refresh()` invalidation issue — possibly the parent `(dashboard)`
layout's React `cache()` wrapper or some Next.js 16 RSC payload behavior.

## What still needs to happen (follow-up)

1. **Diagnose `router.refresh()` invalidation**. Most likely fix is one of:
   - Add `revalidateTag('room-${roomId}')` alongside `revalidatePath`, with
     `unstable_cache` tagged reads in `dashboard-data.ts`.
   - Switch `getProjectDetailForUser` from `cache()` to `unstable_cache` with
     a per-room tag that the action invalidates.
   - Force the page into `dynamic = 'force-dynamic'` for `EditRoomStudio`
     routes.
   - Have `handleDeleteVariant` do an optimistic local state update
     (remove `versions[A]` from the local array) and rely on the action's
     `revalidatePath` only for the eventual canonical state.
2. **Address `state.viewing` initial-state mismatch**. `EditRoomState.viewing`
   defaults to `"original"` from `initialEditRoomState`, but the delete-fallback
   test assumes `viewing` is `"A"` (matching `Room.selectedVariantIndex=0`).
   Either initialize `viewing` from `initialLookbookSlot` in
   `createInitialEditRoomState`, or have the test first click variant A to
   set `viewing` before deleting.
