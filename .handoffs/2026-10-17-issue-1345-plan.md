## Acceptance mapping (from issue body)

1. **Flag-gated mount**: `page.tsx` imports `resolveEditRoomRedesignEnabled` and reads
   `searchParams.room` (when present, takes precedence over the first room); passes
   it as `focusedRoomId` to `buildEditRoomStudioProps`.
2. **Prop mapping from `RefineRoom[]` → studio**: the page already builds `rooms`
   (the `RefineRoom[]`-shaped list); for the new branch we pick the matching room
   (`?room=<id>` or first) and pass it through `buildEditRoomStudioProps(...)`.
3. **`searchParams.room` stays in URL**: `page.tsx` resolves it, hands it to the
   studio; the wrapper does NOT mirror it into any local state. (Studio currently
   takes no URL sync props; URL→state is owned by the host page in client subtree.)
4. **What stays in wrapper vs studio**: host owns project/room data fetch and the
   URL→focused-roomId resolution; studio owns the dual-tab editor + inspector.
5. **Props the studio doesn't accept**: none — `buildEditRoomStudioProps` is the
   complete surface (mirrored from #1344).
6. **Flag-off path**: existing `RefineStudioClient` mount runs unchanged.
7. **Retro compat**: `?room=<id>` query is preserved across the flag toggle (legacy
   path already supports it; new path honors it).
